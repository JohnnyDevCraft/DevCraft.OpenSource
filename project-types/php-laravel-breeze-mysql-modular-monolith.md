# Project Type: PHP Laravel Breeze MySQL Modular Monolith

Use this template to define a type of project that DevCraft can be used to create.

## Description

Creates a Laravel web application organized as a modular monolith, with Laravel Breeze (Blade stack) providing authentication and profile management, MySQL as the database through Laravel Sail, and PHPUnit for automated tests. This project type is for server-rendered web applications that should deploy as one Laravel application while keeping business areas in explicit modules under `modules/{Module}`. Breeze's generated auth code is relocated into an `Identity` module, a single `Shared` module holds intentional cross-cutting code, and a `Sample` module proves the module wiring end to end.

## Setup Guidance

### Step 1

Ask the operator for the setup inputs before creating anything. Do not assume versions.

- {AppName}: Application name used for the Laravel app, `APP_NAME`, and the MySQL database name (snake_cased).
- {PhpVersion}: PHP version to target (for example 8.3 or 8.4). The `php-laravel-modular-monolith` architecture baselines PHP 8.3; record the operator's choice and any deviation in `.devcraft/ARCH.md`.
- {LaravelVersion}: Laravel major version to install (for example latest stable). Confirm it is supported by `laravel/breeze`.

### Step 2

Create the Laravel application at the repository root without a starter kit, configured for PHPUnit.

- {AppName}: Laravel host application.
  - Type: php-laravel-app
  - Physical Path: . (repository root)
- Create with `composer create-project laravel/laravel` pinned to {LaravelVersion} (or `laravel new` choosing no starter kit and PHPUnit).
- In `composer.json`, set `config.platform.php` to the {PhpVersion} patch version (for example `8.3.0`) and run `composer update` so dependency resolution matches the target runtime.

### Step 3

Install Laravel Breeze with the Blade stack and PHPUnit.

- Run `composer require laravel/breeze --dev`.
- Run `php artisan breeze:install blade --phpunit`.
- Run `npm install` and `npm run build` to confirm the Tailwind/Alpine/Vite assets compile.

### Step 4

Configure Laravel Sail with MySQL as the database.

- Run `php artisan sail:install --with=mysql` (add other services only when the operator asks).
- Set the Sail PHP runtime in `docker-compose.yml` to match {PhpVersion}.
- In both `.env` and `.env.example`, set:
  - `DB_CONNECTION=mysql`
  - `DB_HOST=mysql`
  - `DB_PORT=3306`
  - `DB_DATABASE={app_name}`
  - `DB_USERNAME=sail`
  - `DB_PASSWORD=password`
- Remove the default SQLite database file and any SQLite-only configuration left by the installer.
- Configure the testing database in `phpunit.xml` to use MySQL (`DB_CONNECTION=mysql`, `DB_DATABASE=testing`) so tests run against the same engine as the app.
- Run `./vendor/bin/sail up -d` and `./vendor/bin/sail artisan migrate`.

### Step 5

Establish the module convention before moving or adding code.

- Create the `modules/` folder at the repository root.
- Add `"Modules\\": "modules/"` to `autoload.psr-4` in `composer.json` and run `composer dump-autoload`.
- Every module follows this layout:
  - `modules/{Module}/Providers/{Module}ServiceProvider.php`: registers the module's routes, namespaced views (`{module}::`), migrations, and bindings.
  - `modules/{Module}/Http/Controllers`, `modules/{Module}/Http/Requests`
  - `modules/{Module}/Actions`, `modules/{Module}/Models`, `modules/{Module}/Policies`, `modules/{Module}/Events` as needed
  - `modules/{Module}/routes/web.php`
  - `modules/{Module}/resources/views`
  - `modules/{Module}/database/migrations`, `modules/{Module}/database/factories`
  - `modules/{Module}/tests/Unit`, `modules/{Module}/tests/Feature`
- Register each module service provider in `bootstrap/providers.php`.
- Add `modules/*/tests/Unit` and `modules/*/tests/Feature` directories to the Unit and Feature test suites in `phpunit.xml`.
- Keep the Laravel `app/` folder thin: framework host concerns only, no business modules.

### Step 6

Create the seed modules.

- Shared: The one intentional cross-cutting module for reusable code all modules may consume.
  - Type: php-laravel-module
  - Physical Path: modules/Shared
  - Must not contain module-owned business rules or module-owned persistence.
- Identity: Owns authentication, registration, password reset, email verification, and profile management generated by Breeze.
  - Type: php-laravel-module
  - Physical Path: modules/Identity
  - Move Breeze's auth and profile controllers, form requests, `routes/auth.php`, profile routes, auth/profile Blade views, and auth/profile tests into the matching `modules/Identity` folders.
  - Update namespaces to `Modules\Identity\...`, update route registrations to load from the Identity service provider, and update view references to the `identity::` namespace.
  - Keep shared layouts and Blade components used by every module (for example `app-layout`, `guest-layout`) in the host `resources/views` unless the operator chooses otherwise.
  - The `User` model may remain at `App\Models\User` for framework compatibility; record that decision in `.devcraft/ARCH.md`.
- Sample: Proves module wiring end to end.
  - Type: php-laravel-module
  - Physical Path: modules/Sample
  - Include a service provider, one authenticated route, one controller, one Blade view under `sample::`, one migration and model, one factory, one unit test, and one feature test.

### Step 7

Validate the setup before considering it complete.

- `./vendor/bin/sail artisan migrate:fresh` succeeds against MySQL.
- `./vendor/bin/sail artisan test` passes, including the relocated Breeze tests running from `modules/Identity/tests` and the Sample module tests.
- `npm run build` succeeds.
- Register, log in, edit profile, and reach the Sample route in the browser.
- Record the chosen {PhpVersion}, {LaravelVersion}, module layout, and Identity relocation decisions in `.devcraft/ARCH.md` and `.devcraft/AGENT.md`.
